## 1. 측정 개요

압전소자를 밟거나 두드릴 때 나오는 전기 신호를 아두이노로 직접 측정했다.
기존 계산은 전부 문헌값 기반 추정이었고, 이번이 **첫 실측**이다.

| 항목 | 내용 |
|---|---|
| 소자 | PZT 압전 디스크 (Piezo Shock Tap Sensor 모듈에서 원판만 분리) |
| 측정 장비 | Arduino Uno, ADC 직접 제어 |
| 회로 | 압전소자 (+) → A0, (−) → GND **(부하저항·분압기 없음, 직결)** |
| 샘플링 | 62,469 Hz (스케치가 부팅 시 자가 측정) |
| 기준선 | ADC 9 (= 0.044 V) |
| 수집량 | 트리거 이벤트 2건(각 600샘플) + 연속모드 2.17초(2,171샘플) |

측정 코드: [`piezo_capture_simple.ino`](piezo_capture_simple.ino)
분석 코드: [`analyze_v1.py`](analyze_v1.py)
원자료: [`data/piezo_capture_data-1.csv`](data/piezo_capture_data-1.csv)

## 2. 핵심 결과

### 2-1. 이벤트 요약

| event | 피크 전압 | 최저 전압 | 하한 클리핑 | 최대 dV/dt | 공진 주파수 | 감쇠 시정수 τ | 기계적 Q |
|---|---|---|---|---|---|---|---|
| 13 | 0.244 V | +0.088 V | 0.0 % | 1,831 V/s | 521 Hz | 2.07 ms | 3.4 |
| 14 | **1.134 V** | −0.044 V | **29.2 %** | 17,106 V/s | **3,332 Hz** | 0.655 ms | **6.9** |

event 14가 제대로 된 타격이고, event 13은 약하게 눌린 경우다.

### 2-2. 공진 주파수를 실측으로 확인했다

![파형](figures/fig1_waveform.png)

event 14의 파형은 교과서적인 **감쇠 진동(damped oscillation)** 이다.
FFT로 주파수를 뽑으니 **3,332 Hz**.

27 mm 황동 백킹 PZT 디스크의 문헌상 공진 주파수는 3~4 kHz 대역이다.
**측정값이 이 범위 안에 들어온다** — 소자가 정상 동작하고 있고, 측정 체계가
물리적으로 타당하다는 뜻이다.

감쇠 시정수 τ = 0.655 ms에서 기계적 품질계수를 구하면

```
Q_m = π · f_r · τ = π × 3332 × 0.000655 ≈ 6.9
```

Q가 낮다(= 빨리 멎는다). 소자가 단단히 고정되지 않고 바닥에 놓인 상태라
진동 에너지가 빠르게 빠져나간 것으로 보인다.

### 2-3. 걸음 주파수와 공진 주파수가 1,666배 차이 난다

![스펙트럼](figures/fig2_spectrum.png)

이 연구에서 가장 중요한 결과다.

| | 주파수 |
|---|---|
| 사람 걸음 | 약 2 Hz |
| 소자 공진 | 3,332 Hz |
| **비율** | **약 1,666 배** |

압전 발전은 공진 근처에서 출력이 극대화된다. 그런데 걸음은 공진보다
세 자릿수 낮은 영역에 있다. **바닥 타일 방식의 압전 발전이 구조적으로
불리한 이유가 이 그래프 한 장에 들어 있다.**

이 간극은 부하저항 설계에도 그대로 이어진다. 최적 부하는
R_opt = 1/(2πfC) 인데, 주파수가 1,666배 낮으면 최적 저항은 1,666배 커진다.

| 동작 주파수 | 최적 부하 (C_p = 15 nF 가정) |
|---|---|
| 공진 3,332 Hz | 3.2 kΩ |
| 걸음 2 Hz | **5.3 MΩ** |

기존 시뮬레이터에서 쓰던 1 kΩ, 분석기의 10 kΩ은 **둘 다 세 자릿수 틀린
값**이었다. 이번 측정으로 확인된 오류다.

### 2-4. 유도 물리량

부하저항 없이 측정했으므로 전력을 직접 잴 수 없다. 대신 정전용량 C_p를
가정하면 나머지를 유도할 수 있다. (event 14, V_peak = 1.134 V, dV/dt = 17,106 V/s)

| C_p | 전하 Q | 저장 에너지 E | 변위전류 i | 추정 힘 F (d₃₃=400 pC/N) |
|---|---|---|---|---|
| 10 nF | 11.3 nC | 6.4 nJ | 171 µA | 28.4 N |
| 15 nF | 17.0 nC | 9.6 nJ | 257 µA | 42.5 N |
| 20 nF | 22.7 nC | 12.9 nJ | 342 µA | 56.7 N |
| 30 nF | 34.0 nC | 19.3 nJ | 513 µA | 85.0 N |

사용한 식:
- 전하 `Q = C_p · V`
- 저장 에너지 `E = ½ C_p V²`
- 변위전류 `i = C_p · dV/dt`
- 힘 `F = Q / d₃₃`

**C_p가 이 표 전체를 좌우한다. 다음 차시 최우선 과제는 C_p 실측이다.**

## 3. 확인된 한계 — 다음 측정에서 고칠 것

### (1) 음(−) 반주기의 29%가 잘려나갔다

가장 큰 문제다. 아두이노 ADC는 0 V 미만을 읽지 못한다.
기준선이 ADC 9(= 0.044 V)에 불과해서, 음전압 여유가 사실상 없다.

event 14에서 **600샘플 중 175개(29.2%)가 0에 붙어 평평**하다.
fig1 오른쪽 그래프에서 아래쪽이 잘린 모양으로 바로 보인다.

압전소자는 누를 때 (+), 뗄 때 (−)로 진동하므로 **실제 발생 에너지의
절반 가까이가 기록되지 않았다.** 지금 표의 에너지 값은 전부 과소평가다.

→ **해결**: 1 MΩ 저항 2개로 5 V를 나눠 A0에 2.5 V 기준점을 만들면
양쪽 반주기를 모두 읽을 수 있다.

### (2) 부하저항이 없어 전력·효율을 측정하지 못했다

직결 측정이라 이번에 얻은 건 **개방전압(open-circuit voltage)** 이다.
전력 P = V²/R을 구하려면 정해진 부하가 필요하다.

→ **해결**: 10 kΩ ~ 10 MΩ 범위에서 저항을 바꿔가며 P–R 곡선을 그린다.
2-3절 계산에 따르면 최댓값은 MΩ 대에서 나올 것으로 예상된다.

### (3) ⚠️ LED 점등은 발전의 증거가 아니다

측정 중 220 Ω LED가 켜지는 것을 확인했으나, **이 LED는 아두이노 8번 핀이
켠 것**이다. 스케치의 해당 부분:

```cpp
if (d >= TRIG_DELTA) {
    fired = true;
    digitalWrite(LED_PIN, HIGH);   // 두드리는 순간 LED 켜짐
}
```

즉 LED는 **USB 전원**으로 켜진 트리거 표시등이며, 압전소자가 만든 전기로
켜진 것이 아니다. 보고서에 "압전소자로 LED를 점등했다"고 쓰면 사실과 다르다.

→ **압전 발전으로 LED를 켜려면** 아두이노와 완전히 분리해서
`압전소자 → 브리지 정류기 → 커패시터 → LED` 회로를 따로 꾸며야 한다.
이건 다음 차시에 별도 실험으로 해볼 가치가 있다.

### (4) 트리거 이벤트가 2건뿐이다

통계를 내기에 부족하다. 저항 조건당 최소 10회를 목표로 한다.

## 4. 다음 차시 계획

1. **C_p 측정** — LCR 미터, 없으면 알고 있는 저항과의 RC 시정수로 역산
2. **2.5 V 바이어스 추가** — 음 반주기 복원 (한계 (1) 해결)
3. **P–R 곡선** — 10 kΩ~10 MΩ 스윕, 조건당 10회
4. **낙하추 지그** — 타격 세기 고정해 CV 75% 낮추기
5. **독립 LED 회로** — 정류 + 커패시터로 진짜 압전 발전 점등 시도

## 5. 재현 방법

```bash
pip install pandas numpy matplotlib
python analyze_v1.py
```

`data/` 의 CSV를 읽어 `figures/` 에 그래프 4장을 생성하고 요약표를 출력한다.

### CSV 열 설명

| 열 | 뜻 |
|---|---|
| `event` | 트리거 번호 (0 = 연속모드) |
| `n` | 샘플 번호. 트리거 시점이 0, 음수는 직전 구간 |
| `t_us` | 트리거 기준 시간 (µs) |
| `adc_raw` | ADC 원시값 (0~1023) |
| `v_piezo` | 변환 전압 (V) |

`#` 로 시작하는 줄은 측정 설정과 이벤트 요약 메모다.
